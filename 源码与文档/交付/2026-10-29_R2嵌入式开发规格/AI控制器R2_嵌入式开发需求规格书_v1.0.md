# AI 控制器 R2 嵌入式开发需求规格书

文档编号 AICTRL R2 SRS 001　版本 1.0　日期 2026年10月29日
适用对象：嵌入式开发、硬件联调与电脑端软件开发。

本规格定义嘉立创 R2 原理图对应的板级接口、驱动要求、交互协议与验证条件。开发可先开展板级适配、驱动及协议测试；R2 专用固件需完成迁移后才能进入样机联调。现有 REV A 二进制不得直接作为 R2 固件交付。

## 1 版本边界与硬件基线

硬件连接以 2026年10月29日保存的复验网表为依据，且与 R2 保存重开网表完全一致。产品对象为 AI控制器 / Board1 / Schematic1 / P1；原生工程内 Board2 是测试对象。此次规格编制读取本地交付与复验证据，没有重新连接在线 EDA。

| 模块 | R2 实际器件 | 软件开发影响 |
| --- | --- | --- |
| 主控 U1 | ESP32-S3-WROOM-1-N8R8 | 8MB Flash、8MB PSRAM；PCB 天线 |
| 惯性传感 U2 | BMI270 | I²C 驱动与配置文件加载 |
| 麦克风 U3 | SPH0645LM4H-B-8 | 标准 I²S 接收，非 PDM |
| 功放 U4 | MAX98357AETE+T | I²S 播放，无 I²C 寄存器 |
| 充电 U5 | BQ25180YBGR | I²C 配置与充电中断 |
| 触觉 U6 | DRV2605LDGSR | I²C 播放，EN 固定为高 |
| 稳压 U8 | TPS63001DRCR | 固定 3.3V，无软件调压接口 |
| 输入与输出 | 4 个功能键，扬声器与马达接口 | 无电量计、RGB 灯和麦克风电源开关 |

状态标记：硬件事实＝网表连接；沿用要求＝现有交互与协议规则；开发目标＝本规格提出、需测试达成；待冻结＝缺少实物或硬件决定。四类不能互相替代。

验收边界：连接与转板复验 23 项通过；188/244 个引脚电气类型为 Undefined；PCB 仍有 217 条 Connection Error。完整电气验收、正式产品 Layout 准入及制造放行未通过。[S1][S2]

## 保留与禁用

GPIO35、36、37 不分配为外设；N8R8 的 Octal PSRAM 占用相关资源。GPIO0/3/45/46 为启动相关引脚，不能作为任意空闲脚重用。GPIO19/20 留给 USB。[D1]

未连接脚不代表具备可用外部接口：RXD0/TXD0、GPIO1、RGB 候选脚等均没有功能网络。本版没有 UART 调试连接器，也没有 GPIO1 的 VBUS 检测线路。EN 是模组复位输入，不是可配置 GPIO。

# 3 I2C 总线与传感器驱动

IF 02　SDA=GPIO8、SCL=GPIO9；R1/R2 各 4.7kΩ 上拉至 3V3。地址统一使用 7 位格式，不能把已左移的地址再传入驱动。初次联调建议 100kHz；确认上升时间与负载后再使用 400kHz，此为联调目标。

| 器件 | 地址 | 识别或诊断 | 中断 |
| --- | --- | --- | --- |
| BMI270 | 0x68 | 寄存器 0x00 的 CHIP_ID=0x24 | INT1 → GPIO10 |
| BQ25180 | 0x6A | 读状态/故障及 MASK_ID；按手册掩码解释 | /INT → GPIO11 |
| DRV2605L | 0x5A | 读取 STATUS 的设备与故障字段 | 无独立中断，轮询状态 |

总线应由一个管理层串行访问；中断服务仅记录事件，任务上下文再读寄存器。超时与有限重试必须有上限，不能让马达或充电轮询阻塞输入处理。建议单事务超时 20ms、最多重试 2 次；这些是开发目标，需按实测调整。

## DRV 01 BMI270 初始化与数据

SDO 接地选定 0x68，CSB 接 3V3 选择 I²C。使用 Bosch 官方 BMI270 SensorAPI 并锁定版本及配置数据哈希；完成复位、配置文件装载和 INTERNAL_STATUS 初始化成功检查，再启用传感。不能仅凭地址 ACK 或 CHIP_ID 读通就报告 IMU 就绪。[D2][D3]

建议初始参数：加速度 ±4g、陀螺仪 ±2000°/s、两者 200Hz；这是 R2 调试起点，不沿用旧 LSM6 的 240Hz 枚举。校验单位、量程、采样时间戳及溢出；失效时禁止重复上报旧样本。

INT1 的电平、开漏/推挽、锁存和中断源须由驱动明确配置。该线没有外部上拉；若选择开漏，须验证上拉策略，不能依赖上电默认电平。

## DRV 02 相对指向与校准

PCB 安装方向尚未冻结，传感器轴到握持坐标的矩阵须配置化并通过六面静态与单轴转动确认。先完成静止零偏、噪声/死区及时间基准检查；运动中不能自动覆盖静态校准。居中只重建参考姿态，电脑端执行屏幕中心定位。

BMI270 没有本项目已接入的磁力计，不能承诺长期绝对航向。IMU 故障时保留可用的 L/R 点击，停用运动指向并向主机上报；重连不重放历史位移。

# 4 音频采集与播放要求

| 参数 | R2 开发基线 | 依据或约束 |
| --- | --- | --- |
| 接口 | 标准 I²S，全双工共享时钟 | BCLK GPIO4；WS GPIO5 |
| 板级时钟 | 32kHz，左右各 32bit 槽 | BCLK=32,000×64=2.048MHz |
| 麦克风 RX | GPIO6，读取左槽 | SELECT 接地；24bit 格式，18bit 精度 |
| 功放 TX | GPIO7，左槽有效 | SD_MODE 直连 VSYS；无 MCLK |
| 主机语音 | 16kHz / 16bit / 单声道 PCM | 32kHz 经抗混叠滤波后 2:1 抽取 |

AUD 01　32kHz 是 R2 原理图交接提出的联调规划，尚无实物验证。I²S RX/TX 应由统一时钟管理；使用同一控制器的兼容收发配置，避免两个模块分别重配 GPIO4/5。不能继续使用旧 PDM RX 模式和 48→16kHz 的 3:1 滤波参数。[S1][D4][D5]

## 采集与隐私控制

AUD 02　只有语音键持续按住、主机已取得输入归属且明确允许录音时，才能向主机传出有效 PCM。未经许可时输出静音或不发送有效载荷；松键、租约超时、断连、队列溢出和采集故障均关闭软件采集许可、清理在途缓冲，并终止语音会话。不得重放上一段录音。

本电路麦克风 VDD 直连 3V3，没有 MIC_EN。软件停收与清缓冲不等于物理断电。无播放和采集时可停止共享时钟；播放期间麦克风仍可能随时钟工作，固件必须丢弃 RX 数据。若产品要求物理断电隐私，需要硬件改版。

必须验证 WS 槽位、MSB 对齐、符号扩展和采样边沿；用已知音频与逻辑分析仪确定转换，不复制未经验证的移位常数。旧 50ms 稳定等待仅为联调起点，需验证重启采集后的首段音频。

## 播放与资源互斥

AUD 03　功放 GAIN_SLOT 由 100kΩ 接 VSYS，标称硬件增益 3dB。软件音量用 PCM 缩放与渐变实现；无软件关断 GPIO。未播放时 TX 为零；启动、停止和欠载时先输出零，防止残留样本爆音。扬声器参数未冻结前禁用实际有声播放。[D5]

播放输入须重采样至共享 32kHz，右槽置零即可；禁止在录音中切换共享采样率。初版录音期间禁止扬声器播报和马达振动，提示音在录音结束后播放。全双工回声消除不作为首版已支持能力。

# 5 电源 充电与维护按键

硬件路径：USB-C → F1 → BQ25180 IN；电池接 BAT；BQ25180 SYS 形成 VSYS。TPS63001 从 VSYS 生成 3V3，供 MCU、IMU、麦克风及触觉驱动；功放由 VSYS 供电。稳压器 EN 接 VSYS，固件不能独立关闭该 3V3 电源。

## PWR 01 充电参数与状态

BQ25180 通过 I²C 配置。芯片复位值包括 4.2V 电池调节电压、10mA 充电电流、500mA 输入限流；它们不是当前电池包的已批准参数。须建立电芯型号、终止电压、允许充电电流、NTC 曲线和温度范围对应的配置档。[D6]

电池规格未知时不得套用旧 700mAh 假设或任意提高充电电流。开发固件应先读取故障并禁止充电，待配置档通过后才允许；上电到固件接管前仍存在硬件默认行为，因此首次电池接入须采用硬件认可的受控联调条件。

配置采用读改写并保留保留位；写后回读。/INT 为通知，任务中读取并保存状态/故障，按手册处理读清或锁存语义。必须区分输入存在、充电、充满、温度抑制和其他故障；不得把充电状态当 SOC 百分比。

## PWR 02 看门狗与输入来源

首次 I²C 访问会启动充电器看门狗；其超时可能使配置复位，取决于 WATCHDOG_SEL。驱动须显式设定策略并回读：联调可选软件复位模式并每 10s 访问，发生配置回退则重读状态并恢复获批参数。进入睡眠前必须协调该看门狗。[D6]

本板没有 CC 电流识别或 USB PD 协商，也没有 MCU 的 VBUS 检测线。不能由 5.1kΩ CC 下拉推导可取 1.5A/3A；输入预算需受已识别电源及 USB 状态约束。该限制应由硬件与 USB 软件共同关闭，不能仅修改描述符宣称符合规范。

| 开关 | 实际网络 | 处理要求 |
| --- | --- | --- |
| SW5 管理键 | BAT_NTC → GND | 接 BQ25180 TS/MR，与 J2 NTC 共用；不是 GPIO 功能键 |
| SW6 下载键 | BOOT_N → GND | 保持低并复位进入 ROM 下载；正常启动释放 |
| SW7 复位键 | MCU_EN → GND | 硬件复位；启动后动作归零、按住的键先屏蔽 |

SW5 的短按、长按、唤醒和复位阈值随充电器配置变化，须确认 NTC 实物及 TS/MR 策略后测试；禁止沿用普通“电源键”时序。当前没有电池 ADC 分压或电量计，不提供实测电压、SOC 或精确剩余续航。

# 6 按键交互与输入归属

KEY 01　四键均低有效。沿用现有 C 背键功能语义；KEY_DRAW 对应旧软件 S / SIDE。固件负责原始边沿、去抖、互斥和安全释放；电脑端负责圆盘、目标锁定、长短按解释、圈画及确认流程。[S3][S4]

| 按键 | 正常行为 | 主机配合 |
| --- | --- | --- |
| SW1 / L | 鼠标左键，支持按住拖动 | 特殊模式由主机解释，禁止重复点击 |
| SW2 / R | 普通模式右键 | 特殊模式退出由主机实现 |
| SW3 / V | 按下锁定目标；持续按住语音；松开预览 | 两次短按触发居中；短按不开始采集 |
| SW4 / S | 短按圆盘；长按圈画；松开结束 | 主机取得归属后发 DRAW |

| 参数 | 沿用值 | 边界 |
| --- | --- | --- |
| 去抖 | 25ms | 源自 board_config.h，需样机验证 |
| 语音保持 / 双击窗口 | 280ms / 300ms | 主机交互层时序，非两个固件定时器并行判定 |
| 圈画保持 | 180ms | 主机决定开始，设备保留中断与释放约束 |
| 主机租约 | 750ms | 建议心跳每 250ms；超时撤销授权 |
| 触觉单次上限 | 80ms | 沿用控制核心上限，需适配马达 |

## KEY 02 归属和失效处理

默认 owner=POINTER，设备输出普通鼠标。主机完成 HELLO、CLAIM 并获得 ACK 后才接管特殊输入；CLAIM 时若 L/R 仍按住则拒绝。HOST 归属期间不得由设备 HID 和电脑端注入同一点击。

录音与圈画互斥；二者活动期间禁止触觉。实体松开语音键应先关闭采集许可，不等待 25ms 去抖。建议本地截止延迟≤10ms，此为开发验收目标；已经送达主机的数据不能宣称已被设备撤回。

启动、复位、断连、租约超时和模式取消后：释放鼠标、结束录音/圈画、停止触觉、清在途数据；仍按住的键必须等释放再允许新动作。重连建立新 session，拒绝旧序号和旧会话指令。

发送与应用操作各自保留电脑端确认；成功触觉只跟随真实执行回执。设备本身不执行模型任务、不因本地按键发出“已成功”反馈。

# 7 控制协议与命令格式

COM 01　沿用现有 REV A 的版本 1、32 字节控制负载，以便迁移现有电脑端。该格式来自当前 protocol.c / protocol.h；本规格未另建协议，也未宣称 R2 已完成链路实测。[S4]

| 字节偏移 | 长度 | 主机到设备含义 |
| --- | --- | --- |
| 0 | 1 | 协议版本 = 1 |
| 1 | 1 | 命令编号 1～8 |
| 2～3 | 2 | 保留，必须为零 |
| 4～7 | 4 | session，uint32 小端 |
| 8～11 | 4 | sequence，uint32 小端 |
| 12～15 | 4 | 保留，必须为零 |
| 16 | 1 | value，只能为 0 或 1 |
| 17～29 | 13 | 保留，必须为零 |
| 30～31 | 2 | CRC16，低字节在前 |

CRC 覆盖字节 0～29：初值 0xFFFF，多项式 0x1021，非反射，无最终异或。USB Report ID 独立于 32 字节负载；USB 主机 API 如要求在首字节附加 Report ID，则缓冲为 33 字节，不能把 ID 纳入本 CRC。

| 编号 | 命令 | 用途与约束 |
| --- | --- | --- |
| 1 | HELLO | 建立主机连接；使用设备当前 session |
| 2 | CLAIM | 请求 HOST 归属；L/R 按住则拒绝 |
| 3 | KEEPALIVE | 刷新租约，普通数据不能替代心跳 |
| 4 | RELEASE | 释放输入归属及在途动作 |
| 5 | RECORD | value=1 请求录音，0 停止；受实体语音键限制 |
| 6 | DRAW | value=1 开始，0 结束；不能与录音并行 |
| 7 | FEEDBACK | 触觉请求；录音/圈画期间拒绝 |
| 8 | RECENTER | 重置相对参考；录音/圈画时拒绝 |

COM 02　长度、版本、CRC、保留字段或 value 非法时不执行。序号按 uint32 回绕规则判新，重复与旧包不重放；语法合法但被互锁拒绝的命令同样消耗序号。ACK 结果沿用 0 OK、1 BAD_SESSION、2 STALE、3 NOT_CONNECTED、4 HELD、5 CONFLICT、6 INVALID；传输层需处理无 ACK 的超时，不能无限重试。

# 8 状态上报与传输通道

| 字节偏移 | 设备到主机含义 |
| --- | --- |
| 0～3 | 版本；type；owner（0 POINTER / 1 HOST）；按键位图（1 L、2 R、4 V、8 S） |
| 4～7 / 8～11 | session / event_sequence，uint32 小端 |
| 12～15 | 设备 time_ms，uint32 小端 |
| 16 | 标志位：bit0 主机连接；1 音频许可状态；2 音频就绪；3 圈画；4 触觉；5 已校准 |
| 17～19 | 事件值或 ACK 结果；HID 按钮；hardware_faults |
| 20～23 | type=0x80：电压 mV 与 SOC Q8；type=0x81：X/Y int16 位移；普通事件为零 |
| 24～27 | 最近消耗的 command_sequence |
| 28～29 | 28 bit0 battery_valid、bit1 haptic_calibrated；29 保留为零 |
| 30～31 | 同第 7 节 CRC16 |

事件类型沿用：1 EDGE、2 OWNER、3 MIC、4 DRAW_STATE、5 HAPTIC、6 RESET_INPUT、7 CENTER、8 ACK、9 FAULT；0x80 为状态，0x81 为运动。字段布局必须用相同编解码夹具与主机回归。[S4]

COM 03　R2 无电量来源：battery_valid=0，电压与 SOC 数值清零且主机显示“不可用”，不能显示“0%”。不再探测 0x36 MAX17048，也不把该器件缺失记为 R2 硬件故障。旧 mic_power 字段在 R2 只能表示软件音频许可；设备识别信息须注明 board_revision=R2，主机不能显示“麦克风已物理断电”。

## COM 04 USB 与无线职责

USB 基线沿用 HID 鼠标 Report ID 1、32 字节控制 Report ID 2、USB 专用配置 Report ID 3，以及 16kHz 单声道麦克风 UAC。现有 0xCAFE/0x4031 是开发标识，生产身份待分配。新增扬声器输出若要作为 USB 声卡，还需实现 UAC OUT 与主机验收；当前代码只有麦克风流。

BLE 沿用 HID 与自定义 GATT 控制，Wi-Fi 沿用 TLS 语音；USB 优先，只允许一个输入所有者和一条有效语音路径。音频可沿用 10ms 一帧，即 160 个 int16 样本、320 字节 PCM，网络封装继续服从 wifi_audio.c 与接收桥协议。切换传输前先释放输入并结束语音。

沿用既有绑定、配置分片校验和 NVS 机制；配对信息及凭证不得写入常规日志。协议字段如需扩展板型/能力，应通过版本化的设备识别接口或新协议版本协同修改两端，禁止占用版本 1 保留字节。

# 9 启动 状态管理与故障降级

## SYS 01 启动顺序

1　记录复位原因与板型，校验 Flash/PSRAM、配置版本和参数范围。按键先配置输入；I²S 时钟与输出保持静止，不播放、不振动。屏蔽开机时已按住的键。

2　启动 I²C，优先读取并约束充电器；读取 0x68/0x6A/0x5A 预期器件。每个驱动独立报告 absent、initializing、ready、fault。不能因一个器件缺失而无限卡在启动。

3　加载 BMI270 配置并校验初始化；建立音频共享资源但保持采集许可关闭。DRV2605L 先停止 GO 并设置待机；马达配置未冻结时不进行自动校准或播放。

4　启动 USB 或 BLE 控制，发布能力与故障状态；确认时钟、采样及主机握手后才开放对应功能。USB 拔插检测关闭前不能宣布有线模式验收通过。

## HAP 01 触觉适配

DRV2605L EN 直连 3V3、IN/TRIG 接地，只能通过 I²C 管理。停止请求须写 GO=0，再进入软件待机；不能调用旧 GPIO17 关断来替代。依据实际 LRA/ERM 型号计算 rated voltage、clamp 与相关参数，完成状态检查和必要的自动校准后开放效果。[D7]

I²C 失效时不能承诺马达已由独立硬件关断。限制效果时长、禁止无限循环；失联记录“停止未确认”，待总线恢复读取 GO。若验收要求总线故障下仍能强制停止，需新增硬件 EN 控制。旧 C10-100 寄存器配置不能自动代表本版待选马达。

## SYS 02 睡眠与恢复

第一阶段先完成活动态稳定性。进入低功耗前关闭音频许可、输出零并停止共享时钟，停止触觉、保存必要状态并协调 BQ25180 看门狗。唤醒后重新确认器件配置及新会话；GPIO/充电器唤醒条件、功耗与续航均需实测冻结。

| 故障 | 要求 |
| --- | --- |
| IMU 初始化失败 | 停止位移，保留可用点击，显式报告 |
| 音频采集失败或溢出 | 截止上传并清队列，不能重复旧音频 |
| 充电温度或总线异常 | 限制负载，禁止凭缓存状态宣称正常充电 |
| 主机或网络断连 | 释放输入，停止本次会话，不自动重放 |

## P0 待关闭条件

① USB 自供电模式缺少硬件 VBUS 感知：需要硬件提供合规检测，或由 USB 工程明确验证替代方案；BQ 输入状态轮询不能直接等同于合规 VBUS 检测。② 电池型号与 NTC、扬声器阻抗/额定功率、马达类型/额定值待确认，阻塞相应带载测试。

③ 麦克风物理断电与软件停止采集要求存在差异；若必须保留断电能力，应改硬件。④ 旧需求中的 RGB、精确电量显示、外部天线与 N16R8 未出现在当前 R2 实际电路，应由产品与硬件确认接受差异或改版。规格按 R2 连接记录，不替用户默认取消旧需求。

⑤ 电气类型、供电预算、板框/叠层和布局布线仍未完成；已有 KiCad REV A 的通过结果不能移用到嘉立创 R2。所有待定项需记录决定人、版本与验证证据。
