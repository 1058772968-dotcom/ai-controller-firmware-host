一次操作怎么走（6 步）

说 / 打字按住 V 说话；或在灵动岛里打字。两种入口进同一条管道。
锁定现场按下 V 那一刻记下：光标在哪块、前台是哪个软件、截图、辅助功能（AX）控件树。
Jev 判定只做选择题：哪块、什么意图、目标在截图哪个框、动作能否撤回。回答带概率。
分流执行
有把握的已知动作 → 本机直接做（快捷键 / AX / 打开应用）没把握或多步任务 → Claude computer use
预览确认灵动岛显示「我要做什么」。L 确认，R 取消；不可撤回的动作必须确认。
执行回执做完再截图核对，确认成功才亮灯、振动。
Jev 放在哪：Jev 不是编程语言，是 TypeSafe 的判定模型。它读文字和截图，只回四种答案：选一项（Choice）、是否成立的概率（Noul）、打分（Score）、截图上的框（Box）。它不写回复、不写代码、不做多步规划。所以它当「意图路由器」：快速判断要做什么、点哪里；真正多步的操作交给 computer use。沿用已拍板的规则：两道确认、圈画和说话互斥、R 随时退出。

四、开工前要你拍板的 4 件事

1. 「四块」怎么切

本页按层级切：Dock / 应用框架 / 主内容 / 子页面。如果你指的是屏幕几何上的四个象限（左上、右上、左下、右下），意图表要重排。

2. 执行器用哪种

建议首版「本机确定性动作优先、Claude computer use 兜底」：常见动作快且稳，开放任务才走截图点击。也可以全部交给 computer use，简单但更慢。

3. 首发接哪几个软件

每接一个软件就要写一份意图表。建议先接 4 个：Chrome、访达、钉钉、代码编辑器。

4. 截图能不能上云

Jev 和 Claude 都是云端接口，判定要把截图发出去。可以全量发，也可以只发光标所在那一块，或先在本机遮掉敏感区域。
