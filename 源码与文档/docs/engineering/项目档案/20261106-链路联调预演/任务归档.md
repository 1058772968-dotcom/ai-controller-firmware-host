## 上板记录（2026-11-06）

接法：只接 USB。下表“通过”都是读到的实测；烧录用缓存产物，SHA-256 与合入时一致（点亮档 `7beddfa39a533743…`，联调档 `a9bd99c38afb0ad7…`），ESP-IDF 仍是 v5.2.3。

| 关 | 检查 | 结果 | 证据 |
|---|---|---|---|
| G1 | C9、C18 电压和电流 | NOT RUN，需要万用表 | 无 |
| 上板前 | 芯片、存储、安全位 | ESP32-S3 QFN56 rev v0.2，内置 8 MB PSRAM，Flash 8 MB（GD），Secure Boot 和 Flash 加密关 | esptool |
| G2 | Flash、PSRAM、运行分区、VBUS | PASS：`Flash 8192 KB，PSRAM 8192 KB -> PASS`、`ota_0`、`VBUS 存在` | [证据/G2-点亮档串口日志.txt](证据/G2-点亮档串口日志.txt) |
| G2 | 四键事件 | **未验证**：录约 150 秒，0 个事件，心跳键位一直 `0x0`。不确定这段时间是否按过 | 同上 |
| G3 | 枚举 | PASS：4 个 HID 接口（含 0xFF00）+ CDC，`bcdDevice 0x0124`，序列号 `CC68C7ABD364` | `e24ctl.py list` |
| G4 | IMU | PASS：`dt` 约 4.9 ms（约 200 Hz），`cal=2`，零偏 −0.03 / −0.33 / −0.24 °/s | 遥测 |
| G4 | 启动日志（I²C 三地址、`BMI270 就绪`） | PASS：`BMI270 0x68 ACK / BQ25180 0x6A ACK / DRV2605L 0x5A ACK`，`BMI270 就绪 chip_id=0x24`。网页串口在开机 10–14 秒内连上时能看到 | 网页日志 |
| G6 部分 | 遥测 | PASS：串口 98.6 Hz，8 秒 789 行 0 坏行；网页 99 Hz，丢弃行 0 | `e24ctl.py tel on`、网页 |
| G6 部分 | 网页连接 | PASS：WebHID 和 Web Serial 都连上，session 一致，放稳后“静止：是”，控制台无错误 | Chrome，`127.0.0.1:8897` |

风险结论：H1 排除（DMA 模式枚举正常）；H2 排除（hidapi 和 WebHID 都未被拦）；H4 排除（约 200 Hz，未退化成 50 Hz）。其余未测。H6 有部分证据：联调档连续运行到 274 秒未复位，没有 1 分钟掉电，VSYS 未测。

上板发现：

| 编号 | 现象 | 处理 |
|---|---|---|
| B1 | 空片约每 2.75 秒掉线重枚举，`rst:0x7`、`invalid header: 0xffffffff`。这是 Flash 全空的正常表现，README 原写“直接进 ROM 下载”是错的 | 已改 README |
| B2 | 烧录硬复位后约 15 秒打开 CDC，收到 0 字节；而拔插上电后网页 10–14 秒内连上能看到启动日志，只有开头被 512 B FIFO 挤掉，与 A11 一致，但 `复位原因` 这行也被挤掉了。0 字节的原因未查明 | 待查：两种启动方式各复测一次；复位原因需要另想办法保留 |
| B3 | 上位机日志区显示原始 ANSI 颜色码，例如 `[0;32mI (77869) e24: 遥测 开[0m` | 待修：显示前去掉转义序列 |
| B4 | 点亮档运行到约 46 秒时断电一次，复位原因“上电”。不确定是否人为插拔 | 待用户确认；若非人为，查线和接口 |
| B6 | 板子重启后拿在手里一直 `未校准`、`静止：否`，固件不出光标，网页显示已连接，用户看到的是“连上了没反应”。约 1 分 15 秒内 USB 未掉线、session 未变；状态随后自行变为 `可用`。阈值：陀螺抖动 <1.5 °/s，且 \|a\| 偏离 1 g <0.08，连续 1.2 s | 待定：网页给“请放稳”提示；是否保存上次零偏另议 |
| B7 | 期间板子“重启”多次（session 变化，开机日志重复）。后来发现手上有两块板：MAC `…d3:64` 和 `…d3:bc`，首次 `ioreg` 序列号是 `…BC`、esptool 读到 `…64`，当时没有追究。这些断开很可能是换板或拔插，未逐次证实 | 上板记录要写 MAC |
| B8 | 用户反馈按 SW7“整个设备断电”。网表里 SW7 只把 MCU_EN 拉到地，不接电源；板上无电源指示灯。实测（`…d3:bc`）：USB 断开 3.19 s，与按住时长一致，随后 JTAG 口 0.7 s、联调档重新枚举，不用拔插。重启后手持时停在 `未校准`，光标不动，见 B6。EN 复位的复位原因也显示“上电”。3V3 是否跌落未测，要万用表量 C18 | 判为正常复位，待量 3V3 收尾 |
| B5 | 8896 端口被其他服务占用，上位机改用 8897，手柄授权需重新选一次 | 记录，无需改动 |
