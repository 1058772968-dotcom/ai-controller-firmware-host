## 决策

| 决策 | 原因 |
|---|---|
| 录音键绑 **V**，不绑 L/R/S | 固件 `ak_mic_permitted()` 要求 `recording && mic_power && mic_ready && owner==HOST && 按住 V` 同时成立；`AK_RECORD` 在没按住 V 时直接回 `HELD`。换键录音只会得到全零 |
| 默认「只听按键」，接管 HOST 作为可选 | 状态帧每 100 ms 带四键，打开设备即可读，不需要 HELLO/CLAIM，**鼠标不受影响**；只有麦克风闸门需要 HOST 时才点「接管出声」 |
| 麦克风硬约束为板载 | 需求明确不要电脑/手机麦；匹配 `Held-key microphone` / `AI KEY Mic POC`，取流后再校验 track 名字，对不上直接放弃这次录音 |
| 文字经剪贴板粘贴、可选回车 | 中文在终端/编辑器里最稳；**目标应用没到前台就报错退出**，绝不把文字贴到别的窗口 |
| 密钥只进 macOS 钥匙串 | 不进源码、配置、日志；公开仓库里不出现任何密钥 |
| 把语音前缀（「Claude，…」「Cursor，…」）做成一等公民 | 用户要「填进对应的 Agent」，前缀路由是改动最小的落地方式，可在设置里关 |

## 已知问题

1. **HID 写通道会哑掉**：页面开合几次后 HELLO/CLAIM 全部超时，状态帧照常 10 Hz 到达（读方向正常、写方向哑）。对设备做一次 USB 重枚举立即恢复；界面里加了「重置手柄」按钮（`POST /api/controller/reset` → 跑 `tools/usbreset.swift`）。疑似固件 OUT 端点处理（TinyUSB 侧）。
2. **首包可能丢**：刚打开设备就发的 HELLO 没回执；现在先等一帧状态拿到 session，再重试最多 4 次。
3. 剪贴板还原只支持文本；Cursor / VS Code 的 AI 输入框焦点需人工落点。
4. 会话号、租约（750 ms）与 KEEPALIVE（200 ms）强耦合：页面被系统降频会导致接管掉线，启动脚本已加三个 `--disable-*` 开关。
