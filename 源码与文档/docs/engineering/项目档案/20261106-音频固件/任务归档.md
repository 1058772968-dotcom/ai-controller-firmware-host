- 输入：[固件框架规划](../20261106-固件框架规划/固件框架规划.md)、R2 规格书第 4 节（AUD 01–03）、REV A `audio_capture.c`、ICS-43434 手册 DS-000069、MAX98357A 手册。
- 执行者：Claude Code。

## 决策

| 决策 | 原因 |
|---|---|
| 扬声器只做设备提示音，不做 USB 声卡 | 规划的 TX 链路就是提示音；规格说 UAC OUT 要另做主机验收 |
| 提示音默认不响，每次带口令，上限 -30 dB | 规格 AUD 03：参数未冻结前禁用有声播放。这是运行时口令，不是编译开关，便于台架测试，需要用户知情 |
| 新增 `mic` 电平自检 | V 键未验证时也能确认 I²S；只回统计值，不传波形，未突破 AUD 02 |
| 不给隐私闸门留调试后门 | 正向录音必须真按 V，哪怕因此暂时测不了 |
| 增益先定 +12 dB | 按手册灵敏度估的起点，待已知声源标定 |
| 不做 PSRAM 环形缓冲 | 规划写了，但 UAC 路径用 TinyUSB FIFO（40 ms）已够；Wi-Fi 语音做时再加 |

## 手册核对（规划第 9 节的未决项）

| 项目 | 结论 | 依据 |
|---|---|---|
| ICS-43434 支持 32 kHz | 是，高性能模式 fS 下限 23 kHz，SCK 周期 303–2500 ns，2.048 MHz 为 488 ns | DS-000069 |
| 麦克风格式 | 24 bit 补码，MSB 延迟 1 个 SCK，每帧 64 SCK，左声道在 WS 下降沿后 | DS-000069；实物左槽 99% 右槽 0% 印证 |
| 启动时间 | 小于 20 ms，50 ms 等待够用 | DS-000069 |
| 待机 | SCK 低于约 200 kHz 进待机；手册建议停时钟并拉低。当前停时钟后电平未强制拉低 | DS-000069 |
| MAX98357A 声道 | SD_MODE 分压约 3.23 V，高于 B2（1.4 V）为左声道；BCLK 64× 在支持范围内；tON 典型 7 ms | MAX98357A 手册；分压为计算值，未实测 |

## 麦克风 POC：电脑扬声器到硬件麦克风闭环

用户要求把硬件麦克风当电脑麦克风用，并用电脑扬声器播报、硬件麦克风录音自行闭环。V 键未验证，闸门打不开，用户在“按住 V”和“POC 常开固件”之间选了后者。

新增编译档 `E24_PROFILE=micpoc`：**放宽规格 AUD 02**，主机开流即放行，关流即关，设备名改成 `AI KEY Mic POC`。开关 `CONFIG_E24_MIC_POC_OPEN` 默认关；默认联调档二进制仍是 `Held-key microphone`，不含 POC 字符串。此前“不留调试后门”的决定对默认档不变，POC 档只烧台架板，不用于交付。

### 闭环发现的问题

| 问题 | 处理 |
|---|---|
| USB 总线复位不走 TinyUSB 的关流回调，`s_streaming` 留在真。POC 档会导致闸门卡开 | `audio_svc_streaming()` 掉配置时清标志，挂起时不放行。已用重新枚举实测 |
| `miccap.js` 写死 `Held-key microphone`，POC 档页面找不到麦克风 | 两种名字都认 |
| POC 档下“闸门关闭时无声”“真实录音”会误报隐私故障 | 这两项返回跳过并说明不适用，加了测试 |
| 模拟器桩没有 `sdkconfig.h` | 补空桩，对应默认档 |

测试中还排除了这些假象：分析窗口混入扫频造成的 -1458 ppm；希尔伯特边界造成的 0.64 rad 台阶；测试工具同时设主控和通道音量造成的衰减翻倍（UAC 两级累加，固件正确）；`ResetDevice` 后 macOS 恢复配置，这个测试没有判别力，改用重新枚举。

证据：[语音样本](证据/麦克风闭环/语音样本-电脑扬声器到硬件麦克风.wav)、[频谱图](证据/麦克风闭环/频谱-单音扫频语音.png)，以及同目录的测试脚本。频谱图来自修复前的 POC 版本。
