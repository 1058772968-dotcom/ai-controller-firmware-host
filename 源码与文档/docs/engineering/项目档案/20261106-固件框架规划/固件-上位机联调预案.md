## 2 接口约定（固件提供）

### 2.1 USB 身份与接口

| 项 | 值 |
|---|---|
| VID / PID | 0xCAFE / 0x4031（与 REV A 相同的开发标识；量产身份待分配） |
| bcdDevice | 0x0124（E24） |
| 产品名 | `AI KEY E24` |
| 接口 0 | HID，IN+OUT 端点，轮询 1 ms |
| 接口 1–2 | CDC ACM：日志 + JSON 行遥测（`/dev/cu.usbmodem*`） |

HID 报告（与 REV A 描述符相同，电脑端可直接复用）：

| 报告 ID | 方向 | 内容 |
|---|---|---|
| 1 | 设备→电脑 | 标准鼠标（按键 + int8 dx/dy）。仅在 owner=POINTER 时发送 |
| 2 | 双向 | v1 32 字节控制协议（命令 / 事件 / 0x80 状态 / 0x81 运动） |
| 3 | 双向 | 32 字节配置通道（见 2.3） |

### 2.2 v1 控制协议：不改格式，补几条行为约定

- 格式与规格书第 7–8 节、`island-poc/protocol.js` 完全一致，**不占用保留字节**。
- 状态报告 0x80 每 **100 ms** 一次，电脑端从中取 `session`；标志位 bit5 `calibrated` 表示陀螺仪零偏已校准。
- **owner=HOST 时**，位移走 0x81 运动报告：`dx/dy` 为 **int16 计数**（与鼠标同单位，已含灵敏度、加速、平滑），约每 4 ms 一帧，期间不发鼠标报告。电脑端用它自己移光标，**不要再平滑**。
- RECENTER 命令：固件只清亚像素余量和平滑状态；把光标放到屏幕中心由电脑端完成。
- **租约到期**：只有持有输入（HOST、录音、圈画、触觉）时才走断连流程，释放输入并换 session。已 RELEASE 或只发过 HELLO 的空闲连接到期后只清 `host_connected`，session 不变，不打断系统鼠标。这是与 REV A 的差异。
- **HELLO** 不释放输入；CLAIM 成功时才隔离当时按住的键。
- 本固件档**未实现音频、触觉、充电配置**：`hardware_faults` 会置 bit1（音频）和 bit2（触觉），所以 RECORD=1 和 FEEDBACK=1 会返回 INVALID。电脑端应据此显示“暂不可用”，不能当作失败重试。

### 2.3 配置通道（报告 3）：指向参数与调试

与 REV A 的 Wi-Fi/BLE 配置事务共用帧格式，操作码从 0x10 起，不冲突。

请求：`[0]=1 [1]=op [2..3]=0 [4..7]=session [8..11]=事务号 [12..27]=负载 [28..29]=0 [30..31]=CRC16`（CRC 同 v1）
回复：`[1]=op|0x80 [2]=结果 [3]=指向状态(0 未校准/1 校准中/2 可用) [12..27]=当前参数 [28]=遥测开关`

| op | 名称 | 负载 |
|---|---|---|
| 0x10 | 读参数 | 全 0 |
| 0x11 | 写参数（立即生效，不落盘） | 16 字节参数 |
| 0x12 | 保存到 NVS | 全 0 |
| 0x13 | 开始陀螺仪校准（需静置 ~1.2 s） | 全 0 |
| 0x14 | CDC 遥测开关 | `[0]=1/0` |
| 0x15 | 重启进下载模式 | `"DFU!"` |
| 0x16 | 恢复默认参数（不落盘）。**轴映射也会重置**，并触发重新校准；只想恢复手感时用 0x11 写默认值并带上当前轴向 | 全 0 |

结果码：0 OK，1 帧错误，2 session 不符，3 参数非法，4 存储失败。

16 字节参数编码（小端）：

| 偏移 | 字段 | 单位 / 默认 |
|---|---|---|
| 0–1 | 灵敏度 counts_per_deg ×100 | 默认 2800（每转 1° ≈ 28 计数） |
| 2–3 | 加速倍率 ×100 | 180（高速时 1.8 倍） |
| 4 | 加速起点 °/s | 30 |
| 5 | 加速满点 °/s ÷2 | 125（=250 °/s） |
| 6 | 死区 °/s ×10 | 7（0.7 °/s） |
| 7 / 8 | 平滑起点 / 终点 °/s | 4 / 15 |
| 9 | 平滑时间常数 ms | 40 |
| 10 | 点击冻结 ms | 70 |
| 11 | bit0 反 X，bit1 反 Y，bit2 重力补偿 | 0b100 |
| 12 | 设备 X/Y/Z 取传感器哪一轴（各 2 bit） | 0b100100（恒等） |
| 13 | bit0–2 设备轴取反 | 0 |
| 14–15 | 保留，必须为 0 | — |

### 2.4 CDC 遥测（开发版）

op 0x14 打开后，CDC 口每 10 ms 输出一行 JSON。和日志混在同一口，**以 `{` 开头的行才是遥测**，其余是日志，电脑端不要把设备文字当命令执行：

```json
{"v":1,"type":"imu","t":12345,"dt":0.0050,"g":[0.12,-0.40,3.10],"a":[0.010,0.020,0.998],
 "h":3.05,"vv":-0.10,"dx":1,"dy":0,"bias":[1.20,-0.80,0.50],"cal":2,"still":0}
```

`g/a` 为传感器原始轴（°/s、g），`h/vv` 为处理后的水平/竖直角速度，`cal` 同指向状态。

## 3 陀螺仪当鼠标：难点与两端分工

| 难点 | 不处理的后果 | 固件做什么 | 上位机做什么 |
|---|---|---|---|
| 零偏（静止也有读数） | 光标自己漂 | 上电后找连续 1.2 s 静止求零偏，期间不出光标；之后只在偏差 <0.6 °/s 持续 >1.5 s 时慢速跟踪温漂（时间常数约 10 s）；**运动中不改零偏**；op 0x13 可手动重校 | 状态 bit5 未置时提示“请把手柄放稳 1 秒”；设置页给“重新校准”按钮 |
| 握持时手腕滚转 | 往右转，光标却斜着走 | 用加速度估计重力方向，把角速度分解成“绕世界竖直轴（左右）/绕水平轴（上下）”。仿真：滚转 45° 时斜移 1:1 降到 15:559 | 无 |
| 手抖 | 光标停不住、难点中小目标 | 软死区 0.7 °/s（按比例衰减，没有台阶感）+ 慢速时平滑 | **不要再平滑**。两端都平滑是“跟手感差”最常见的原因 |
| 跟手（延迟） | 拖着走、有“橡皮筋”感 | 平滑只在 <15 °/s 生效，快速时直通（仿真：甩动第 1 帧就出位移）；数据就绪中断驱动；HID 1 ms 轮询；int8 超出的部分留到下一帧，不丢 | HOST 模式直接用 0x81 位移移光标，每帧立即应用，不排队 |
| 精细 vs 快速 | 小目标点不准，大屏要甩很多次 | 加速曲线：30 °/s 以下 1 倍，250 °/s 以上 1.8 倍 | 提供灵敏度/加速滑块，op 0x11 实时生效、0x12 保存 |
| macOS 自带鼠标加速 | POINTER 模式下被系统再加速一次，手感和调参值对不上 | 无法关闭系统行为 | 特殊模式用 HOST + 0x81 自己移光标（不经过系统加速）；普通鼠标模式提示把系统“跟踪速度”调到中档并固定 |
| 点击时手一抖 | 按下的瞬间光标跑开，点歪 | 任一键按下或松开后 70 ms 丢弃位移 | 无 |
| 放在桌上 / 离手 | 光标漂移 | 静止时死区内输出为 0；零偏持续跟踪 | 无 |
| 没有磁力计 | 不能做绝对指向 | 只做相对指向，不承诺航向 | 双击 V 时发 RECENTER，并把光标放到屏幕中心 |
| PCB 安装方向未冻结 | 上下左右反了或串轴 | 轴映射与取反可配（参数第 12–13 字节），改了自动要求重新校准 | `e24ctl.py wizard`：平放、前端竖起两个静止姿势读重力定轴（比转动稳），X 轴按右手系算出；写入后重新校准，再用向右转、向上抬核对方向；保存由用户确认 |

默认值来自旧 GRIP 上位机（灵敏度 28、死区 0.7、1.2 s 校准），其余为仿真起点。**手感必须上手调**：仿真只证明算法行为方向对，不代表手感通过。

## 4 交给上位机会话的清单

1. 传输：用 HID 打开 VID 0xCAFE / PID 0x4031。报告 2 收发 32 字节 v1 帧（`protocol.js` 现成），报告 3 收发配置帧。如果 API 要求，在首字节附带报告 ID，且 ID 不计入 CRC。
2. 从 0x80 状态取 session；按规格书握手：HELLO → CLAIM → 每 250 ms KEEPALIVE（租约 750 ms）。
3. HOST 模式下用 0x81 的 `dx/dy` 移光标，不做二次平滑；断连或 RELEASE 后交还系统鼠标。
4. 显示 `calibrated` 和 `hardware_faults`：IMU 故障时提示，录音和振动显示“本固件档不可用”。
5. 调参页面：读参数（0x10）→ 滑块改值（0x11）→ 保存（0x12）；“重新校准”（0x13）；“轴向向导”（读 CDC 遥测）。
6. 可选：CDC 遥测实时曲线，方便明天调手感。

## 5 明天上板快速流程

前提：R7 首板，只接 USB 不接电池。命令都在 `engineering/e24/` 下执行。

1. 点亮档（可选，约 5 分钟）：`E24_PROFILE=bringup tools/idf.sh -p /dev/cu.usbmodem* flash monitor`，按 `engineering/e24/README.md` 的 M1 清单核对。
2. 联调档：`tools/idf.sh -p /dev/cu.usbmodem* flash`。这一步写入的是带 TinyUSB 的固件，重启后原来的 JTAG 串口消失，出现 HID 和新的 CDC 口。
3. 看日志：`screen /dev/cu.usbmodem* 115200`（新的 CDC 口），应看到 I2C 三个地址的探测结果、`BMI270 就绪`，放稳 1 秒后出现 `陀螺仪已校准`。
4. 不开上位机，直接当鼠标试：左右键点击，转动手柄移光标。
5. 调轴向和手感（先退出第 3 步的 `screen`，否则 CDC 口被占）：双击 `prototype/启动实机上位机.command`，按 `prototype/aikey-host/README.md` 的上板流程走；网页打不开设备时用命令行后备 `python3 tools/e24ctl.py info` → `wizard` → `still` → `tune` → `save`。两者不要同时占 CDC 口。
6. 全量联调：在同一页面点「接管指针」试 HOST 模式和 0x81，再进灵动岛演示。
7. 再次烧录：TinyUSB 运行时 esptool 不能自动复位。可以运行 `python3 tools/e24ctl.py dfu`，或 `stty -f /dev/cu.usbmodemXXXX 1200`（这两种方法都未实测）；不行就按住 SW6（BOOT）点一下 SW7（复位）。

## 6 未验证与风险

- 全部未上板：BMI270 初始化、中断极性、I2C 时序、USB 枚举、CDC 控制台、进下载模式都只在编译层面成立。
- 轴向默认按“+X 右、+Y 指向屏幕、+Z 正面朝外”，实际取决于 PCB 在壳内的安装方向，需要用轴向向导确定。
- 手感参数只经过仿真，必须上手调。
- 本档没有 UAC 麦克风、播放、触觉和充电配置；BQ25180 只做了地址探测，充电参数保持芯片默认，**不要接电池联调**。
- 上位机已确认用 WebHID。注意两点：① HOST 归属期间固件不发系统鼠标报告，网页之外的系统光标会停住，页面失焦或隐藏时应发 RELEASE，失焦期间不重连（后台标签页定时器被限流时，750 ms 租约到期也会自动交还系统鼠标）；② 报告 1（鼠标）属于浏览器受保护的集合，WebHID 读不到，所以 POINTER 模式下的光标移动在网页里看不到，这是正常的。
- 网页和 `e24ctl.py` 的帧、参数和向导逻辑都已对固件同一份 C 代码测试；真实 USB 读写、macOS 权限、浏览器设备授权和手感都没有实测。
- IMU 运行中连续读失败 10 次后停用指向，**重启才恢复**。
- **CDC 口上日志和遥测是两路独立写入**，高频时可能在行中间交错，“以 `{` 开头的行是遥测”这条约定**不保证每行完整**。遥测本身放不下整行时整行丢弃。上板时先检查；电脑端解析遥测要容错（JSON 解析失败就丢弃这一行）。如有问题，后续改为遥测与日志走同一写入路径，或拆成两个 CDC 口。
