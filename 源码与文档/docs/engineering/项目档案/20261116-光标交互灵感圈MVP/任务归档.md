## 关键决定

| 决定 | 理由 |
|---|---|
| 原生 Swift 菜单栏 App，不用 Python | 用户要“本地 App + 基础权限”；权限要授给 App 本身。签名身份固定，重新编译后不用重新授权 |
| Jev 只做判断，执行留在代码里 | Jev 是 System One 判断模型（不是编程语言），返回带概率的选择；“点它”由辅助功能 AXPress 执行 |
| 候选来自辅助功能，不发截图 | 选出来的一定是屏幕上真实存在的元素；Jev 图片输入要“危险区”请求头且仍为预览；截图上云是提案里未拍板的边界 |
| 没有 Key 时用模拟模式 | 界面、日志和流程能先跑通；模拟只看距离和方向，明确标“模拟” |
| 圈选和意图先用键盘快捷键 | E24 板上 L/R/V/S 未接好（同日部署归档），S 键圈选、按住 V 说话留到按键接好后 |
| 第一版就做圈选和灵感库，不只做点击预判 | 评审模型建议只做点击预判；用户贴的需求核心是“圈起来—说明意图—灵感库—丢进 agent”，只做预判会漏掉主体，所以三块都做最小版 |

和提案的关系：本 MVP 相当于提案 P0/P1 的一小片（单步“点它”、圈选、意图），但不涉及多步接管、computer use、四块切片和意图包。提案第 10 节的待拍板项（尤其是“上位机直接操作电脑是否列为新能力层”“截图上云边界”）仍未拍板；本次按用户要求先做可调试的 MVP，不代表这些已定。

### 缺口

- 小红书、B 站、推特真实页面上的 F2 / F3 **未测**（要在用户自己的账号上操作，由用户来按）。
- 快捷键在 App 里的整条路径（按键 → 查找 → Jev → 确认框 → 按下 → 回读）没有由我实际触发：按全局快捷键会作用在用户当前看的页面上。已验证的是核心查找与按下（测试页）和单元测试。
- ⌃⌥← / → 是否和用户装的其他软件冲突：注册成功（`app.jsonl` 无失败记录），但不代表别的软件没有先占用。

## 已知限制

- 枚举耗时差异大：Claude 40–80 ms，Dia、钉钉 280–440 ms。都是串行 AX 调用，后续可减少采样点或缓存。
- Jev 判断依据只有文字和几何，读不到辅助功能信息的软件（自绘界面、画布、部分 Electron）找不到候选，会显示“无候选”。
- 发给 TypeSafe 的内容含窗口标题、网址和光标附近元素文字（不含截图）。README 和设置窗口里写明了。
- Key 曾出现在对话记录里，建议调试后到 TypeSafe 控制台轮换。
