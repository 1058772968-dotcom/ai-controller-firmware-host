# AI KEY 实机上位机

单页工具：[AI键盘-实机上位机.html](../AI键盘-实机上位机.html)。对接 E24 联调档固件，完成[联调预案](../../docs/engineering/项目档案/20261106-固件框架规划/固件-上位机联调预案.md)第 4 节清单。

双击 [`prototype/启动实机上位机.command`](../启动实机上位机.command) 打开，需要桌面版 Chrome 或 Edge。它和灵动岛 POC 共用同一个本机服务，手柄授权也共用。

## 功能

| 区域 | 内容 | 走哪条通道 |
|---|---|---|
| 设备 | Session、归属、校准状态、故障、四键 | 报告 2（0x80 状态） |
| 指向参数 | 滑块实时生效，保存到 NVS，重读，恢复默认（保留轴向） | 报告 3：0x10 / 0x11 / 0x12 |
| 重新校准 | 静置约 1.2 秒 | 报告 3：0x13 |
| 轴向向导 | 平放定 +Z，竖起定 +Y，X = Y×Z，写入后转动核对 | 报告 3 + CDC 遥测 |
| 角速度曲线 | 水平/竖直角速度、零偏、静止、采样率 | CDC 遥测（Web Serial） |
| 试手板 | 普通鼠标模式看系统光标；接管后用 0x81 位移驱动圆点 | 报告 2 |
| 进下载模式 | 点两次确认 | 报告 3：0x15 |

## 逐项测试

页面最上方的面板，9 项按顺序点，判定逻辑在 `bench.js`，取流在 `miccap.js`。结果存在本机浏览器，可复制成文本。

| 项 | 怎么判 |
|---|---|
| 连接与固件 | 收到状态、音频命令有回应；旧固件在这里就会提示 |
| 陀螺仪校准 | 放稳等校准完成 |
| 遥测 | 3 秒内至少 90 Hz、丢弃 0 行 |
| 四键 | 四个键按下和松开都收到；缺哪个点名对应焊盘 |
| 麦克风电平 | 左槽非零过半、右槽几乎为零、没有 I²S 错误；只读电平 |
| 麦克风响应声音 | 拍手比安静时峰值高至少 10 dB |
| 闸门关闭时无声 | 取流 2 秒全零，而且设备确认主机在收流，防假通过 |
| 真实录音 | 按住 V 才有声，按 V 前和松键 300 ms 后都是零；录音只在内存里，可回放 |
| 扬声器提示音 | 勾选“已接好”才能开始，音量上限 -30 dB，人耳判断 |

麦克风取流要授权，第一次可能短暂打开默认麦克风以读取设备名，不读数据。录音和四键测试会接管指针，切走页面会交还。

## 约定

- **默认不接管**：连上后不发 HELLO/CLAIM，配置通道只核对 session，所以调参时系统光标照常可用。点「接管指针」才进 HOST；切走页面自动 RELEASE，离开期间不重连，回来重新接管。L/R 按住时接管会被拒绝，松开后自动重试。
- **界面以设备回显为准**：滑块写入后用回复里的参数重绘，因为固件会量化（灵敏度 ×100、死区 ×10、加速满点 ÷2）。
- **一次一帧**：拖动滑块只保留最新一份，发完再发下一帧。
- **恢复默认保留轴向**：固件的 0x16 会连轴映射一起清掉，所以这里改用 0x11 写默认值并带上当前轴向。
- **串口固定 115200**：固件把 1200 bps 当作“重启进下载模式”。打开后要置 DTR，否则固件不写遥测。
- **遥测容错**：只收能解析的完整 imu 行，其余按日志显示或丢弃计数。设备文字只显示，不执行。
- 向导方法与 `engineering/e24/tools/e24ctl.py` 相同，两边可以互换。

## 上板流程

1. 烧录联调档（预案第 5 节），只接 USB，不接电池。
2. 双击启动，点「连接手柄」选 AI KEY。放稳 1 秒，等「已校准」。
3. 点「连接遥测串口」，选新出现的 usbmodem 口。串口被 screen 占用时先关掉。
4. 跑轴向向导，通过后点「保存到手柄」。
5. 转动手柄调灵敏度、死区、平滑，满意后保存。
6. 按四个键看指示灯，点「接管指针」试 0x81 位移。
7. 点「灵动岛演示」进入 POC，同一授权下继续联调。

## 虚拟手柄

没有实物时点「虚拟手柄」看界面、走流程。它故意按错位方向安装，好让向导有事可做。数据是模拟的，不算验证证据。

## 构建与验证

```sh
npm run check:host && npm run test:host && npm run build:host
```

`host.test.js` 共 16 项。对端是固件同一份 C 代码：把 `engineering/e24/tests/host/devcfg_shim.c` 和 `aikey_core` 编译到临时目录，JS 编出的帧直接喂给它。覆盖：

- 500 组随机参数经固件量化后逐字节一致，越界、保留位、session、CRC、存储失败的结果码；
- 24 种安装方向写入后，经真实 `pointer.c` 右转光标向右、抬头光标向上；
- 轴向推导与 `e24ctl.py` 的 `derive_axes` 结果一致；
- 遥测解析、请求队列、仅调参不抢鼠标、WebHID 与 Web Serial 接线（假设备）、向导全流程。

## 边界

- **没有接过实物**：USB 枚举、WebHID 打开设备、报告 3 真实收发、Web Serial 打开 CDC、手感都没验证。
- 接管时只移动页面里的圆点，不控制系统光标。网页做不到跨应用常驻或移动系统光标，这需要原生 Mac 程序。
- 本固件档没有触觉，页面显示“暂不可用”。录音走系统麦克风（UAC），不经过这个页面；麦克风自检和提示音用 `e24ctl.py mic`、`e24ctl.py tone`。

## 麦克风 POC 档

板子烧 `E24_PROFILE=micpoc` 时，系统里的麦克风叫 `AI KEY Mic POC`，不按 V 也放行。页面能照常取流；「闸门关闭时无声」和「真实录音」两项显示跳过，因为“必须全零”在这一档按设计不成立。验证隐私闸门要烧回默认联调档。
