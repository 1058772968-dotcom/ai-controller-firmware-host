# 智慧呆毛 · 灵动岛 POC

离线单页：[AI键盘-灵动岛POC演示.html](../AI键盘-灵动岛POC演示.html)。智慧呆毛住在 Mac 的刘海里，平时只露出一点点。用四个键、陀螺仪和马达，在三种模式、五个场景之间流转：

| 模式 | 场景 | 一句话 |
|---|---|---|
| 创作 | CAD 改模 | 圈出零件上的两个孔，说「改成 M4 沉头孔，外沿倒 C2」，在左侧确认后写入特征树 |
| 创作 | 网页微调 | 在按钮上涂一笔，说出想要的样子，在左侧确认前后对比和代码补丁后应用 |
| AI 协助 | 整理桌面 | 圈住整个桌面说「清理一下」，呆毛跳下灵动岛逐个观摩，三个子 Agent 拿出方案 |
| AI 协助 | 空间诊断 | 圈住「磁盘已满」提示，问「为啥又满了」，呆毛钻进存储条找出根因，只清能重建的文件 |
| 办公 | 语音办公 | 不用键盘鼠标：倾斜扫过邮件（每封轻震一下），L 打开，说出总结和回复，确认后发送并加入日程 |

## 交互语法（沿用 C 背键与 V0.3 定义）

| 输入 | 行为 | 触觉 |
|---|---|---|
| S 短按 | 灵动岛展开成「流转」卡片；倾斜左右挑选，L 进入，R 收起 | 展开、每格轻点、落地 |
| S 按住 ≥180 ms | 圈选（CAD、桌面、存储）或涂抹（网页）；松开后闭合 | 圈画期间禁振，闭合时“嗒嗒” |
| V 按下 | 锁定指针下的目标；按住 ≥280 ms 开始说话，松开结束 | 录音期间禁振，结束后补发 |
| V 双击（300 ms 内） | 指针回到屏幕中心，发送 RECENTER | 轻点 |
| L | 确认应用 / 打开 | 成功：“嗒—嗒啦” |
| R | 返回上一步：取消预览 → 清除选区 | 轻点 |

录音和圈画互斥。每个触觉脉冲不超过 80 ms（固件 FEEDBACK 上限）。AI 只给出预览，L 确认后才执行，并只在执行回执后才振动报告成功。

和 V0.3 的差异（POC 提案）：S 短按原先打开光标旁的六项圆盘，本 POC 改为展开灵动岛，以便在应用和模式之间流转。普通鼠标模式下 L/R 不变。

## 三种输入

- **键鼠模拟**（默认）：在屏幕里移动鼠标代替倾斜指向；左键是 L、右键是 R；按住 D 或 F4 是 S，按住空格或 F3 是 V；1/F1、2/F2 也对应 L/R。右侧按键面板可以直接点按。
- **AI KEY 实物**（WebHID）：在桌面版 Chrome 或 Edge 中，从 `http://127.0.0.1` 打开页面，点击「连接 AI KEY」。筛选条件为 `cafe:4031`，厂商页 `0xFF00`，报告 2，32 字节 v1 协议。连接后发送 HELLO 和 CLAIM，每 200 ms 发一次 KEEPALIVE。取得 HOST 归属后：
  - 四键来自 `buttons` 位图，指针由 0x81 的 `dx/dy` 直接驱动，不做二次平滑；
  - 圈画时发 DRAW，录音时发 RECORD，振动时发 FEEDBACK，V 双击发 RECENTER；
  - 会话变化时作废旧按键并重新握手；
  - 断连后释放所有按键，回到模拟。
  - HOST 期间固件不发系统鼠标报告（报告 1）。页面失焦或切到后台时主动发 RELEASE，把系统光标交还系统；回到页面后重新 HELLO → CLAIM。
  - 报告 1 属于浏览器保护的鼠标集合，WebHID 读不到，所以普通鼠标（POINTER）模式下的移动在页面里看不到，这是正常的。
  - `hardware_faults` 的 bit1（音频）和 bit2（触觉）置位，或命令返回 INVALID 时，显示「本固件档暂不可用」，不再发送这两类命令。
- **语音**：默认使用每个场景的示例话术（V 按住时逐字显示）。勾选「用电脑麦克风识别」后改用浏览器语音识别；Chrome 走在线服务，识别失败时退回示例话术。

## 部署

- **本机（可接实物）**：双击 [`prototype/启动灵动岛POC.command`](../启动灵动岛POC.command)。它在 `127.0.0.1:8896` 起一个静态服务（端口被占用时自动往后顺延），并用 Chrome 打开本页。WebHID 只在安全上下文可用，用 `file://` 直接打开时连不了 AI KEY。关闭终端窗口即停止服务。
- **在线（只能虚拟演示）**：`node island-poc/build.mjs --artifact <输出路径>` 另出一份去掉页面骨架、标记为托管环境的版本，发布到 claude.ai Artifact（私有，需在页面 Share 里授权给别人）。受限框架里不能直连 USB，也不能用麦克风，所以「连接 AI KEY」只提示改用本机启动，语音走示例话术。

## 构建与验证

```sh
npm run check:island && npm run test:island && npm run build:island
```

`island.test.js` 共 12 项，覆盖按键语义（短按/长按、锁定/说话/双击居中、互斥、复位）、CRC 与命令编码、状态与运动解码、HID 握手与归属、失焦释放与回焦重新接管、E24 固件档能力降级，以及触觉脉冲上限。

协议另与固件做过交叉验证：用本机 `cc` 编译 `engineering/rev-a/firmware/core/protocol.c`。固件可以解码本页编出的 HELLO、FEEDBACK、DRAW，并拒绝保留字节非零的命令；本页也能正确解出固件编出的 0x81 运动报告（dx=-37, dy=512）。

## 边界

- AI 修改、子 Agent、文件整理、磁盘清理和邮件收发都是本地脚本演示（示例结果）：不调用模型，不改动真实文件，也不控制系统。
- 实物通道按 REV A / E24 联调约定实现，但还没有接过样机。在固件联调之前，不能算已经联通实物。
- E24 首版固件没有音频和触觉。马达只在屏幕上用波形示意；V 键的语音走电脑麦克风或示例话术。
- 用户给的视频号参考链接无法在本环境打开。灵动岛的动效按需求文字自行设计，没有对照参考视频。
